# Markdownで脚注を表現できるようにする

- 状態：完了（mainへマージ済み。現状の仕様は[docs/specs/markdown-pipeline.md](../specs/markdown-pipeline.md)を参照）

## ユーザーストーリー

書き手として、記事にGFM標準の記法（`[^1]`と`[^1]: …`）で注釈・出典・補足を添えたい。読者が本文と脚注を行き来でき、RSSリーダー上でも同じように読めるようにしたい。

## 背景（着手時の事実）

- このサイトのMarkdownパイプラインはGFMが既定で有効なため、脚注はすでにパースされHTMLへ変換されていた。課題は「脚注を動かす」ことではなく、公開できる品質への仕上げ
- 未整備だった点：
  - 脚注セクションの見出しが英語（`Footnotes`）、戻りリンクの`aria-label`も英語（`Back to reference 1`）
  - 見出しに付く`sr-only`クラスに対応するCSSがサイトに無く、見出しが本文の`h2`と同じ大きさでそのまま見えていた
  - RSS全文配信のsanitizeが`id`属性を落とすため、リーダー上で参照と定義のジャンプリンクが機能しない
  - 記法ガイドに脚注の記述が無い
- 角括弧構文とは衝突しない（`[^1]`はメソッドの丸括弧を持たないため変換対象にならない）

## 価値（なぜやるか）

- 注釈・出典を本文の流れを切らずに添えられる表現手段が増える。
- GFM標準記法の採用により、実装コストが最小で、一般的なエディタの支援も効く。

成功の判定：脚注を含む記事が、サイト本体とRSSの両方で読める・行き来できること。

## スコープ

### やること

- 脚注ラベル（見出し・戻りリンク）の日本語化
- 脚注セクションのスタイル調整（本文との調和）
- RSS全文配信でのジャンプリンク対応
- 記法ガイドへの追記

### やらないこと

- 角括弧構文への脚注メソッドの追加（参照と定義の2部構成はインライン中心の設計に合わない）
- 脚注以外のGFM機能（表・タスクリストなど）の変更
- 同一の脚注を複数箇所から参照したときの体験の作り込み（標準の挙動に委ねる）

## 受け入れ条件（すべて達成済み）

- [x] 本文に`[^1]`と`[^1]: 内容`を書くと、参照リンクと文書末尾の脚注セクションが生成され、相互にジャンプできる（`.md`／`.mdx`の両方）
- [x] 脚注セクションの見出しと戻りリンクのラベルが日本語になっている
- [x] 脚注の本文中で強調・リンクなどのインライン記法が使え、外部リンクには`target="_blank"`と`rel`が付く
- [x] feed.xmlの`content:encoded`で参照・定義の`id`が保持され、リーダー上でジャンプが機能する
- [x] 記法ガイドに脚注の節とサンプルがある
- [x] 脚注の記述ミス（定義のない参照など）でビルドが落ちない

## 採用した方針

- **ラベルの日本語化**：`astro.config.ts`の`remarkRehype`オプションで設定する。見出しは「脚注」、戻りリンクは「参照Nに戻る」、戻りリンクの表示は`↩`＋異体字セレクタU+FE0E（環境による絵文字表示を防ぐ）
- **スタイル**：`packages/react`の`Prose.module.css`に追加。脚注セクションは上に区切り線と余白を置き、本文より小さい文字サイズにする。見出しは自明なため視覚的に隠す（クリップ方式。読み上げには残る）。参照と定義を行き来したとき飛び先がビューポート上端に貼りつかないよう`scroll-margin`を設定。公開パッケージの変更のためchangesetを追加
- **参照の表記**：実装の過程で`rehypeFootnoteReference`プラグインを追加し、`<sup><a>1</a></sup>`を全角括弧つきの`（*1）`表記（`<span data-footnote-ref-wrapper>`）へ差し替えた
- **RSS**：`feed-integration.mjs`のsanitize設定で`id`属性を全要素で許可し、`a`の`aria-label`・`aria-describedby`も残す。`toAbsoluteUrls`はフラグメントリンク（`#`始まり）を対象にしないため変更不要
- **ドキュメント**：記法ガイドに脚注の節を追加（GFM標準記法であり独自記法ではない旨を明記）

方針として、出力HTMLを後段で文字列置換するようなハックは避け、ライブラリが提供する設定と標準的なCSS・rehypeプラグインの範囲で実現した。

## 作業の分割（実績）

1. `remarkRehype`オプションによるラベルの日本語化
2. `Prose.module.css`への脚注スタイルの追加とchangeset
3. sanitize設定の`id`許可（RSS対応）
4. 記法ガイドへの追記と、`.md`／`.mdx`双方・feed.xmlでの動作確認
5. 参照表記（`（*1）`）とマークアップの調整

## リスクと軽減策（当時の判断）

| リスク | 対応 |
| --- | --- |
| ページをまたいで同じ脚注ID（`user-content-fn-1`など）が生成され、複数アイテムを1画面に表示するRSSリーダーでジャンプ先が衝突しうる | GFMとRSS全文配信の一般的な制約として許容した |
| MDXでGFMの脚注が効かない可能性 | MDX統合はMarkdown設定を継承しており、`.md`と`.mdx`の双方で表示を確認した |
| 本文の`text-align: justify`が脚注の短い段落で不自然に見える | 脚注セクションのスタイル調整で対応した |
